# MySync

MySync — кроссплатформенная программа для синхронизации файлов между компьютерами в одной локальной сети.

Проект предназначен для Windows и CachyOS/Linux. Программа работает без облачного сервера и центрального управляющего устройства.

> Текущий статус: реализована основа локального ядра — сканирование и сравнение файлов, план первой синхронизации, SQLite-состояние, JSON-конфигурация, проверенная запись новых файлов и резервирование перед удалением. Сетевой обмен, CLI, фоновый режим и установка пока не реализованы. Описанные ниже команды MySync и сборки — целевое поведение, а не доступные команды.

## Зачем нужен проект

MySync создаётся как простой локальный аналог Syncthing для личного использования и обучения. Главная цель проекта — получить полностью понятную пользователю систему, которая самостоятельно поддерживает одинаковое содержимое выбранной папки на нескольких компьютерах.

Программа не использует облачное хранилище и не требует постоянного центрального сервера. Каждое устройство является самостоятельным узлом: оно хранит локальное состояние файлов, обнаруживает другие узлы, обменивается сведениями об изменениях и принимает решения по синхронизации.

Проект также предназначен для практического изучения:

- работы с файловой системой и путями;
- вычисления хешей и проверки целостности;
- сетевого программирования через TCP и UDP;
- проектирования протокола обмена;
- локального хранения состояния в SQLite;
- создания CLI-приложений;
- фоновых процессов и автозапуска;
- кроссплатформенной сборки Python-приложений.

## Модель работы

Каждый компьютер с MySync состоит из трёх логических частей:

1. **Файловый сканер** — изучает корневую папку, находит файлы и каталоги, вычисляет SHA-256 и собирает метаданные.
2. **Локальное состояние** — SQLite хранит сведения о предыдущих синхронизациях, устройствах, изменениях и конфликтах.
3. **Сетевой узел** — обнаруживает устройства в локальной сети и передаёт служебную информацию и файлы по TCP.

Корневая папка выбирается пользователем отдельно на каждом компьютере. Например:

```text
Windows:  C:\Users\User\Documents\MySyncData
Linux:    /home/user/MySyncData
```

Путь может отличаться, но относительная структура внутри корневой папки должна совпадать.

## Жизненный цикл устройства

### Первый запуск

При первом запуске MySync:

1. запускает мастер первичной настройки;
2. просит выбрать корневую папку;
3. просит указать имя устройства;
4. создаёт уникальный ID устройства;
5. проверяет доступ к папке;
6. проверяет и выбирает свободные сетевые порты;
7. настраивает автозапуск;
8. запускает CLI-меню обнаружения устройств.

Если папки нет, программа предлагает создать её. Если нет прав доступа, сначала предлагает исправить права или выбрать другую папку, а затем при необходимости запрашивает права администратора.

### Первичное подключение

В CLI пользователь включает обнаружение устройств. MySync показывает найденные узлы в локальной сети. Для каждого устройства отображаются:

- имя;
- уникальный ID;
- IP-адрес;
- состояние доверия;
- шестизначный код подтверждения.

Пользователь выбирает устройства по одному. Устройство считается доверенным только после проверки кода на обоих компьютерах.

После подтверждения устройство сохраняется в локальном списке доверенных. При следующих запусках повторно подтверждать его не нужно, пока пользователь сам не удалит его из списка.

### Первая синхронизация

Первая синхронизация запускается пользователем из CLI-меню. MySync полностью сканирует обе корневые папки и строит объединённую картину содержимого:

- файл только на первом устройстве передаётся на второе;
- файл только на втором устройстве передаётся на первое;
- одинаковые файлы считаются синхронизированными;
- одинаковые пути с разным содержимым становятся конфликтами;
- пустые каталоги также учитываются;
- удалённые состояния учитываются по истории и времени изменения.

Передача не считается завершённой, пока принимающая сторона не проверит SHA-256.

### Последующая работа

После первичной настройки MySync работает в фоне. При появлении доверенного устройства в локальной сети узлы обмениваются состояниями. Если конфликтов нет, безопасные изменения могут синхронизироваться автоматически.

Если обнаружены конфликты или ошибка передачи, фоновый процесс открывает терминал и показывает CLI-меню. Пользователь получает возможность разобраться с проблемой вручную.

## Способы управления

MySync предусматривает несколько уровней управления.

### Мастер первичной настройки

Используется один раз на новом устройстве. Через него задаются базовые параметры:

- корневая папка;
- имя устройства;
- подтверждение создания папки;
- подтверждение настройки автозапуска;
- первичный поиск устройств.

Порты, уникальный ID и технические параметры сеть выбирает автоматически.

### Интерактивное CLI-меню

Команда без параметров открывает основное меню:

```text
MySync
```

Меню должно позволять:

- запустить синхронизацию;
- посмотреть найденные устройства;
- добавить и подтвердить новое устройство;
- удалить устройство из доверенных;
- открыть список конфликтов;
- выбрать доминирующую версию;
- посмотреть состояние текущей синхронизации;
- просмотреть ошибки и важные операции;
- проверить состояние автозапуска;
- запустить повторную проверку папки.

### Команды CLI

Помимо интерактивного меню предусматриваются отдельные команды:

```text
MySync
MySync sync
MySync devices
MySync conflicts
MySync settings
MySync logs
MySync status
```

Названия команд являются рабочим предварительным контрактом и могут быть уточнены до реализации CLI.

Назначение команд:

| Команда | Назначение |
| --- | --- |
| `MySync` | открыть интерактивное меню |
| `MySync sync` | запустить ручную синхронизацию |
| `MySync devices` | показать найденные и доверенные устройства |
| `MySync conflicts` | открыть список конфликтов |
| `MySync settings` | открыть настройки |
| `MySync logs` | показать журнал операций и ошибок |
| `MySync status` | показать текущее состояние узла |

### Фоновый режим

Фоновый процесс используется для работы без постоянно открытого терминала. Он:

- запускается вместе с системой;
- слушает сетевые объявления MySync;
- обнаруживает доверенные устройства;
- обменивается сведениями о файлах;
- выполняет безопасную синхронизацию;
- сохраняет результаты в SQLite;
- открывает CLI при конфликте или ошибке.

Фоновый режим не означает постоянное отслеживание каждого изменения файла в MVP. В реальном времени изменения пока не отслеживаются. Обмен запускается вручную или при обнаружении доверенного устройства.

### Будущий системный трей

После MVP планируется управление через значок в системном трее. В нём должны отображаться:

- запущен ли MySync;
- с какими устройствами установлено соединение;
- текущий процент синхронизации;
- количество ошибок;
- количество конфликтов;
- кнопки запуска синхронизации и открытия CLI.

## Основная идея

MySync объединяет содержимое двух устройств. В результате на каждом устройстве должны находиться все файлы, которые были хотя бы на одном из устройств.

Используется одна корневая папка синхронизации. Пользователь выбирает её самостоятельно на каждом компьютере; пути к папке могут различаться.

Все файлы и вложенные каталоги внутри корневой папки синхронизируются без разделения на группы.

## Согласованное поведение

### Синхронизация

- Первая синхронизация запускается через CLI-меню.
- В MVP синхронизация выполняется полным сканированием папки.
- Изменения определяются с помощью SHA-256 для каждого файла.
- Новые файлы передаются на другое устройство.
- Изменённые файлы обновляются после проверки SHA-256.
- Пустые папки также синхронизируются.
- Переименование в MVP рассматривается как удаление старого файла и создание нового.
- Отслеживание изменений в реальном времени добавляется позже.

### Удаления и конфликты

- Последний известный статус файла считается актуальным независимо от устройства, на котором он появился.
- Последнее удаление также считается актуальным и распространяется автоматически.
- Удалённые и заменённые версии хранятся 7 дней.
- При одновременных изменениях автоматически выбирается более поздняя версия по времени UTC.
- Старая версия сохраняется как резервная.
- Если одинаковый путь уже существует на обоих устройствах, но содержимое различается при первой синхронизации, возникает конфликт.
- Конфликты разрешаются через CLI-меню.
- Пользователь может выбрать доминирующее устройство для всей синхронизации, папки или отдельного файла.
- При наличии конфликтов безопасные файлы синхронизируются, а конфликтные остаются без изменений.
- При первом разрешении конфликта программа запрашивает подтверждение. Позже режим можно настроить: применять решение сразу или спрашивать каждый раз.

### Правило последнего состояния

Для каждого относительного пути MySync должна хранить историю состояний. Состояние может быть одним из следующих:

- файл создан;
- файл изменён;
- файл удалён;
- файл восстановлен из резервной копии.

При сравнении устройств программа определяет последнее состояние по времени UTC. Если последнее состояние — изменение, актуальная версия распространяется на другие устройства. Если последнее состояние — удаление, файл удаляется на других устройствах после сохранения резервной копии.

Если временные отметки недостаточны или устройства изменяли один файл независимо друг от друга, создаётся конфликт. Автоматическое решение не должно уничтожать старую версию: она сохраняется на 7 дней.

## Безопасность и защита данных

В MVP MySync работает только в доверенной локальной сети и не использует шифрование. При этом программа должна защищать данные от повреждения и случайной перезаписи:

- неизвестное устройство не получает доступ к синхронизации без подтверждения;
- каждое устройство имеет уникальный ID;
- передача проверяется SHA-256;
- файл сначала записывается во временный файл;
- основной файл заменяется только после успешной проверки;
- конфликтные версии не удаляются автоматически;
- резервные версии хранятся ограниченное время;
- SQLite-база остаётся локальной и не передаётся как обычный файл.

Шифрование сетевого обмена, защита через ключи и синхронизация через интернет относятся к следующим этапам.

### Резервные копии

Резервные копии хранятся в служебной папке `_mysync` внутри корневой папки. Папка имеет имя с нижним подчёркиванием и дополнительно помечается скрытой системными средствами Windows и Linux.

Резервные файлы получают уникальные имена с указанием устройства и времени, например:

```text
_mysync/report__device-a__2026-10-16_143000.bak
```

Содержимое `_mysync` синхронизируется, но уникальный ID и имя текущего устройства сохраняются локально. SQLite-база каждого устройства не синхронизируется.

### Устройства и сеть

- В MVP используется локальная сеть через Wi-Fi или Ethernet.
- Автоматическое обнаружение устройств работает уже в MVP.
- Ручной ввод IP-адреса остаётся резервным способом подключения.
- Новое устройство отображается в CLI-меню с именем, ID, IP-адресом и кодом подтверждения.
- Устройства подтверждаются по одноразовому шестизначному коду.
- Новые устройства добавляются по одному.
- Подтверждённое устройство сохраняется в списке доверенных между перезапусками.
- Доверенное устройство можно удалить через CLI-настройки.
- В MVP используется доверенная локальная сеть без шифрования.
- Bluetooth и синхронизация через интернет планируются позже и запускаются только по запросу пользователя.

Порты программа проверяет и выбирает самостоятельно. Пользователь не должен искать или настраивать порты вручную.

### Фоновая работа

- После первичной настройки MySync работает в фоне без открытой консоли.
- Программа устанавливается в автозапуск на Windows и CachyOS/Linux.
- Если доверенные устройства обнаружили друг друга и конфликтов нет, синхронизация запускается автоматически.
- При обнаружении конфликтов или ошибки открывается терминал с CLI-меню.
- Позже планируется значок в системном трее с процентом выполнения и текущим статусом.

## Первичная настройка

При первом запуске пользователь указывает:

- корневую папку синхронизации;
- имя устройства.

Устройство получает уникальный ID автоматически. Если корневая папка не существует, программа предлагает создать её и запрашивает подтверждение.

Если у программы нет доступа к папке, сначала открывается CLI-меню с предложением исправить права или выбрать другую папку. При необходимости затем запрашиваются права администратора.

Изменение корневой папки после первичной настройки пока не входит в MVP.

## Работа с файлами

- В MVP синхронизируются содержимое, размер и время изменения файла.
- Время изменений сравнивается в UTC.
- Если SHA-256 одинаковый, содержимое считается неизменённым; используется более позднее время изменения.
- Права доступа, атрибуты Windows и другие метаданные пока не синхронизируются.
- Символические ссылки пока не поддерживаются.
- Скрытые и системные пользовательские файлы синхронизируются; список исключений появится позже.
- Имена файлов сравниваются без учёта регистра.
- Если в Linux одновременно существуют `Report.txt` и `report.txt`, синхронизация папки блокируется до ручного исправления имён.
- Если файл занят другой программой, MySync открывает CLI-меню и просит закрыть файл. Запрос повторяется до освобождения файла.

## Передача файлов

В MVP файлы передаются целиком через TCP.

Полученный файл сначала записывается во временный файл. После передачи выполняется проверка SHA-256, и только после успешной проверки временный файл заменяет основной.

Если хеш не совпал:

1. MySync повторяет передачу.
2. При повторной ошибке удаляет временный файл.
3. Оставляет исходный файл без изменений.
4. Показывает ошибку пользователю.

Передача частями и возобновление после разрыва соединения планируются позже.

Если доверенное устройство недоступно, в MVP показывается ошибка. Очередь незавершённых операций и автоматические повторы будут добавлены позднее.

## Хранение данных

Для каждой установки используется локальная SQLite-база. Предварительно согласованы таблицы:

- `devices` — устройства, их ID, имена, IP и статус доверия;
- `files` — последнее известное состояние каждого относительного пути;
- `file_events` — изменения и удаления с временем, устройством и SHA-256;
- `conflicts` — файлы, требующие ручного выбора;
- `sync_runs` — запуски синхронизации и их результаты.

Настройки, резервные копии и журналы хранятся в `_mysync`. Уникальный ID и имя устройства остаются локальными при пересборке и синхронизации.

## CLI

Интерфейс и сообщения MySync будут на английском языке.

Предполагаемые операции CLI:

```text
MySync
MySync sync
MySync conflicts
MySync devices
MySync settings
MySync logs
```

Во время синхронизации CLI показывает:

- текущий файл;
- общий процент выполнения;
- количество обработанных файлов;
- ошибки.

Журнал содержит ошибки и важные операции. Логи хранятся в `_mysync` и автоматически удаляются через 7 дней.

## Сборка и запуск

В MVP создаются отдельные автономные исполняемые файлы для Windows и CachyOS/Linux:

```text
MySync.exe  # Windows
MySync      # CachyOS/Linux
```

Сборка должна включать Python и необходимые зависимости.

Первичная сборка выполняется из каталога с корневой папкой проекта:

```text
build_first MySync
```

Команда первичной сборки устанавливает программу, настраивает автозапуск и выполняет первичную настройку.

Для последующих запусков используется:

```text
build MySync
```

Команда `build MySync` проверяет локальные файлы проекта и утилиты. Если обнаружены изменения, она показывает их и пересобирает программу только после подтверждения пользователя. При повреждении или отсутствии исполняемого файла выполняется полная пересборка.

При пересборке сохраняются пользовательские данные, резервные копии, база, имя и уникальный ID устройства. Старые данные помечаются как относящиеся к предыдущей сборке. Локальные параметры вроде портов не переносятся: программа выбирает порты заново.

Полноценный установщик планируется после MVP.

## План развития

### MVP

- две установки MySync в локальной сети;
- автоматическое обнаружение устройств;
- ручное подтверждение по коду;
- одна корневая папка;
- полное сканирование;
