# Архитектура MySync

## Статус и границы первого шага

Документ задаёт направление архитектуры на основании README и запроса пользователя
начать реализацию небольшого модуля ядра. Сейчас реализуется только вычисление
SHA-256. Сеть, установка, фоновая работа и синхронизация пока не реализованы.

## Структура

```text
src/
  path_test.py           # существующий учебный пример, сохраняется
  mysync/
    __init__.py
    core/
      __init__.py
      hashing.py        # первый реализованный модуль
tests/
  test_hashing.py
docs/
  architecture.md
pyproject.toml
```

Исходники приложения размещаются в пакете `mysync` внутри `src/`.
Учебный пример не является частью библиотеки и не импортируется при её загрузке.
Импорт пакета не запускает сканирование, сеть или запись файлов.
Первый шаг использует только стандартную библиотеку Python, включая unittest.

## Будущие компоненты

- `core` — хеширование, модели состояния и планирование операций.
- `filesystem` — сканирование, временные файлы и резервные копии.
- `storage` — локальная SQLite-база и JSON-настройки.
- `network` — обнаружение, подтверждение устройств и передача по TCP.
- `application` — координация сканирования, сравнения и применения операций.
- `cli` — мастер настройки, меню и связь с фоновым процессом.
- `platforms` — автозапуск и открытие терминала на Windows/Linux.

Это план разделения ответственности, а не уже существующие модули.
Пустые реализации и заглушки для будущих компонентов сейчас не создаются.
Ядро не зависит от CLI, сети или особенностей платформы. Прикладной слой
связывает компоненты; сетевой код не определяет правила удаления файлов.

## Контракт первого модуля

```python
from mysync.core.hashing import sha256_file

digest = sha256_file(path)
```

`sha256_file(path: pathlib.Path) -> str` читает файл в бинарном режиме
блоками не более 1 МиБ и возвращает 64 символа SHA-256 в нижнем регистре.
Пустые, бинарные файлы, Unicode и пробелы в пути поддерживаются.
Файл не изменяется; дескриптор закрывается и при ошибках чтения.
Ошибки файловой системы (например FileNotFoundError, PermissionError,
IsADirectoryError) передаются вызывающему коду без замены пустым результатом.

Результат описывает прочитанный поток байтов. Защита от одновременного изменения
файла будет обязанностью будущего сканера; этот модуль не создаёт снимок файла.

## Проверка

Из корня проекта, без установки зависимостей:

```sh
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

В PowerShell:

```powershell
$env:PYTHONPATH = "src"
python -m unittest discover -s tests -v
```

## Решения для следующих этапов

Перед реализацией следующих компонентов нужно уточнить их контракты:

- отличать начальное объединение файлов от последующих удалений по истории;
- определить время удаления: сканер видит отсутствие файла, а не точное время удаления;
- согласовать автоматический выбор поздней версии и случаи ручного конфликта;
- определить поведение пустых каталогов, удаление которых отдельно не отслеживается;
- отделить локальную базу и идентичность от синхронизируемых данных `_mysync`;
- исключить рекурсивное создание резервных копий и бесконечный обмен журналами;
- подобрать механизм обнаружения при автоматически выбранных TCP-портах;
- определить способ скрытия `_mysync` на Linux: универсального атрибута Windows hidden там нет;
- определить начальный запуск команд сборки до установки программы.

Эти вопросы не препятствуют независимой реализации хеширования.
